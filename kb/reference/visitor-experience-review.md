# Visitor experience and search readiness

Prepared for Ahimanikya Satapathy, Founder & Editor-in-Chief. This candidate connects the existing 67-page preview more clearly. It changes navigation and sharing presentation, preserves the selected content boundary, and prepares a search-launch decision. Implementation and checks are by the same AI assistant, not an independent reviewer.

## What changed for readers

Destination, food, language and literary pages now show a compact path back to their collection. Existing regional breadcrumbs stay in charge on visitor-detail pages. On phones, food and cultural story contents open on request; their links follow the order of the article. This keeps the story opening clear without removing navigation.

Related reading uses the existing editorial connections. Mudhi Mansa now leads to Santali with an explanation of the Mayurbhanj connection. Literary and language endings also offer the language directory, literature and destination guides. These are reading suggestions, not verified travel routes or claims that one cuisine represents a whole language community.

Sharing metadata now uses each entry’s existing credited photograph where suitable. Script SVGs and missing portraits retain an explicitly described brand illustration. The build checks titles, descriptions, canonical addresses, image files and image descriptions. The proposed sitemap is a review artifact, not a public sitemap.

## Search launch decision

Recommendation: retain preview indexing controls for this batch. The candidate sitemap contains 65 proposed public reading and service pages, excluding the error page and personal journey workspace. Its URL list is generated from the exact selected edition rather than the entire research or draft collection.

Before enabling discovery, choose the actual indexable page subset, approve its editorial readiness, generate the served sitemap from that subset, and change crawler controls together in a separate reviewed release. Pages remaining in preview need their own noindex control. Store, internal brand-review routes, held drafts and private visitor plans must not enter that list. Search Console submission and social-network preview inspection have not been performed.

The [discovery audit](../records/evidence/visitor-experience/discovery-review.json) records metadata and fallback-image coverage. A successful build check does not establish how a search engine will index a page or how a social platform will crop/cache its image.

## Follow-up: bounded search proposal

The [public-launch readiness candidate](../records/public-launch-readiness-review.json) supersedes the broad 65-URL sitemap proposal above with an explicit 11-page first-search recommendation. Every one of the 67 published routes now has a proposed, held or excluded decision in the website edition's search-candidate file. This is preparation, not Founder editorial acceptance or search activation.

The separate local search-review output contains the proposed sitemap, crawler file and per-page indexing tags. The ordinary coastal build and publication workflow still ship the existing noindex preview. Approval of website refinements alone does not activate search: the Founder must approve the precise search subset and its editorial wording in a subsequent release. Search Console setup/submission is not included.

The proposed crawler file allows access to held pages so their noindex tags can be read. Neither crawler controls nor an omitted sitemap entry make public content private. The store remains absent from the published edition. Google documents these distinctions in its [noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing) and [sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
